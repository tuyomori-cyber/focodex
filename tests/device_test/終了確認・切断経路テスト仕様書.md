# Focodex 終了確認・切断経路 実機テスト仕様書

作成日: 2026-10-31。対象はSurfaceのFirefox、Focodex拡張、再インストール済みNative Host、Codex CLI。モデル一覧・実行後の終了確認と診断記録、および通常の停止・切断経路を確認する。

## 前提・準備

- 再インストール前から開いているFocodexタブを閉じ、新しく開いた画面で「Hostへ接続」を押す。旧Hostとの接続が残ったままでは更新版を確認できない。
- 試験用リポジトリを選び、許可対象・開始プロジェクトを確認する。ファイルやGit状態を変更しない指示を使う。
- 各試験の日時、対象、画面結果、追跡ID、合否を控える。切断前にIDが表示されなければ時刻と操作種別を控える。
- ログは通常 `~/.local/state/focodex/operation-diagnostics.jsonl`。Hostに `XDG_STATE_HOME` が設定されていれば、その配下の `focodex/operation-diagnostics.jsonl`。ローテーション時は同名の `.1` も確認。`at` はUTC。
- 同じ `traceId` の行を照合する。端末では次の文字列を実際のIDに置き換える（既定パスの場合。`rg` がなければ `grep -F` を使用）。

  ```sh
  rg -F 'ここに追跡ID' ~/.local/state/focodex/operation-diagnostics.jsonl
  ```

- `cleanup_group_check` の `attempts` は確認回数、`waitedMs` は最初の確認開始から判定までの経過ミリ秒。OSのスケジューリングで実測時間は多少前後する。`attempts: 1`、`waitedMs: 0` は即時消滅確認の正常例。ログを共有する前は内容を確認する。

## 中止条件・復旧

「専用プロセス群の終了を確認できません」、前回終了未確認、その他の想定外の状態が出たら、以降の試験を止め、時刻・画面表示・追跡ID・同IDのログを控える。`config.execution.json` を手動削除しない。`/proc` の読取可能な状態件数が0でも消滅の証明にはならない。

正常な未確認記録はOS再起動後、次の操作時にboot IDの変化を確認して解除される。FirefoxやHostの再起動だけでは解除されない。破損記録はOS再起動でも自動解除されず、個別調査が必要。再起動前に他の作業を保存する。

## テストケース

推奨順序: **D-01 → D-02 → D-07 → D-03 → D-04 → D-05 → D-06**。通常操作と対象切替を先に確認し、その後に停止・切断を試す。

### D-01 モデル一覧取得・終了確認

1. 「モデル一覧を再取得」を押し、画面と追跡IDを控える。
2. 同じIDの `model_page_received`、`cleanup_signal`、`cleanup_leader_exit`、`cleanup_group_check`、`terminal` を確認する。
3. 失敗がなければ合計5〜10回連続で取得し、各回の追跡ID・`outcome`・`attempts`・`waitedMs`・終端結果を記録する。

期待結果: 一覧が表示され、`cleanup_group_check.outcome` は `gone`、`attempts` は1以上、`waitedMs` は0以上、`terminal.status` は `completed`、`processGroupGone` は `true`。`attempts: 3, waitedMs: 100` は再確認の例であり実値は固定しない。`attempts` が2以上で `gone` なら実機での再試行成功を確認できる。全回で即時確認されても合格とし、実機の再試行経路は未検証と記録する。再試行の異常系は自動テストで確認する。

### D-02 Codex通常実行・再実行

1. モデルを選び、次の指示を送信する。

   > ファイルの読み書きやコマンドの実行はせず、「Focodex接続成功」とだけ回答してください。

2. 完了後、画面の応答と追跡ID、該当ログを確認する。同じ操作をもう一度実施する。

期待結果: 応答と「完了」が表示され、各回で `cleanup_group_check.outcome: gone`、`attempts`・`waitedMs`、`terminal.status: completed`、`processGroupGone: true` が記録される。2回目も成功する。

### D-03 停止ボタン

1. ファイルの読み書きやコマンド実行を禁止したうえで長めの文章を回答させ、「Codex実行中…」の表示と「停止」ボタンの有効化を確認してから、実行中に押す。
2. 画面と追跡ID、ログを確認し、終了後にモデル一覧を再取得する。

現在の画面は生成途中の応答を逐次表示せず、終了後にまとめて表示するため、応答の表示開始を停止の目印にはできない。「Codex実行中…」はHostの起動通知であり、モデルの生成開始を証明しない。停止のタイミングを控え、応答開始前・生成中を厳密には区別できないことを記録する。将来は応答開始前の停止も区別して検証する。

期待結果: 停止要求が受理されれば「停止要求中…」を経て終了確認後に「停止済み」となる。「接続・実行情報」の `stopDiagnostics.process.processGroupGone` が `true`、ログの `cleanup_group_check.outcome` が `gone`、その後の一覧取得も成功する。停止前に自然完了した場合は通常完了として記録し、停止経路は未検証として再試験する。

### D-04〜D-06 共通: プロセスの3時点観測

SurfaceへのSSHから次の読み取り専用コマンドを実行し、**各ケースの試験前、Codex実行中、切断・終了後かつ再接続前**に結果を比較する。待機中のケースは試験前と切断後も確認する。

```sh
pgrep -af 'codex|focodex'
ps -eo pid,ppid,pgid,sid,stat,cmd | grep -E '[c]odex|[f]ocodex'
```

試験前から存在する他のCodex・Hostを区別し、実行中に現れたHostとその子のPID、PPID、PGID、SID、状態、起動時刻を可能な範囲で控える。実行中の観測を済ませてから切断し、終了処理の時間を少し置いて再接続前に再観測する。短時間で完了して対象を識別できなければ、その回は残存確認を未判定とする。PIDは再利用されうるので番号だけで同一性を断定しない。

プロセス名だけでは対象を特定できず、コマンドの出力には他のCodexや検索コマンド自体が含まれうる。`cmd` にはパスや引数などの機微情報が含まれうるため、共有前に確認・伏せる。終了後も対象らしいプロセスが残る、または所属が判断できない場合は試験を止め、記録して調査する。手動で無関係なプロセスを終了しない。観測は一時点の参考情報であり、離脱した全子孫の終了を完全には証明しない。

### D-04 タブの再読み込み

1. 待機中にタブを再読み込みし、再接続して一覧取得を確認する。
2. 別の回でD-03と同じ安全な指示を送り、「Codex実行中…」になったら共通手順で実行中のプロセスを観測してから再読み込みする。
3. 共通手順で再接続前にプロセスを観測し、再接続してモデル一覧を取得する。旧操作のIDが分かればログも確認する。

期待結果: 新しい接続で一覧取得ができ、旧操作の結果が新しい操作の結果として受信されない。直後に別タブ実行中の排他エラーが出た場合は少し待って状態を確認し、長時間続く場合は中止する。切断した旧操作は `terminal` が記録されない場合があり、その不在だけで終了成功とは判断しない。

### D-05 タブの閉鎖

1. 待機中にタブを閉じ、Focodexを開き直して再接続・一覧取得する。
2. 別の回でD-03と同じ安全な指示を実行し、「Codex実行中…」になったら共通手順で実行中のプロセスを観測してからタブを閉じる。
3. 共通手順で再接続前にプロセスを観測し、開き直して再接続・一覧取得する。IDが分かれば旧ログも確認する。

期待結果: D-04と同じ。切断後の旧結果が新接続の結果に混入しない。

### D-06 Firefox正常終了

1. 待機中にFirefoxを正常終了して起動し直す。一時拡張の場合は再度読み込み、Focodexに接続して一覧取得を確認する。
2. 別の回でD-03と同じ安全な指示を実行し、「Codex実行中…」になったら共通手順で実行中のプロセスを観測してからFirefoxを正常終了する。
3. 共通手順で再接続前にプロセスを観測し、起動し直して再接続・一覧取得する。IDが分かれば旧ログも確認する。

期待結果: 正常な終了処理後に一覧を取得できる。終了未確認となった場合は中止条件に従う。

### D-07 リポジトリ変更

1. D-03と同じ安全な指示を実行し、実行中に開始プロジェクトとワークスペースの選択が無効であることを確認する。
2. 完了後、別の登録済みリポジトリを選択し、モデル一覧を取得する。
3. 新対象でD-02の指示を送り、新しい追跡IDと応答を確認する。

期待結果: 実行中に通常UIから対象を切り替えられず、完了後の新対象の処理は新しい要求・追跡IDで完了する。**既知の表示上の制約:** 切替直後に旧応答が画面に残るため、新対象の応答と判断しない。この表示は未修正事項として記録する。

旧応答表示の修正は今回の終了確認実機テスト完了後に、独立した変更・別コミットとして行う。

## 今回は対象外

Firefox・Hostへの強制終了、SIGKILL、プロセスグループ離脱、権限拒否、1秒以上の残存の人工的な発生は隔離環境で別途検証する。通常実機テストの成功だけではHost強制終了後の孤児防止や全子孫の終了を保証できない。異常系の判定と記録保持は自動試験でも確認する。
