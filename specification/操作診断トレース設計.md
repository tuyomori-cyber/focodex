# 操作診断トレース設計

更新日：2026-10-31

## 目的

Focodexで「操作不可」または途中停止となった事後に、Firefox、Native Host、Codex app-server のどの層まで処理が進んだかを安全に特定する。これは会話履歴や端末間同期の機能ではない。

## 対象と追跡ID

Native Hostは、`id` を持つ要求を受信した時点で公開可能なUUID形式の`traceId`を発行する。入力検証、設定読込、実行ロック、Codex起動より前の拒否も同じIDで記録する。`token`、Native Messaging本文、カーソルの生値は記録しない。

初期実装の対象は`models`と`run`である。各Codex RPCについて送信、応答、例外、EOF、タイムアウト、終了処理を記録する。モデル一覧ではページ番号、候補件数、表示可能件数、次ページ有無だけを保存する。

## 保存先と保護

- 保存先：`$XDG_STATE_HOME/focodex/operation-diagnostics.jsonl`。未設定時は`~/.local/state/focodex/`。
- 親ディレクトリは本人所有の`0700`、ログは本人所有の通常ファイル`0600`。シンボリックリンク、他者所有、group/other権限の対象は拒否する。
- 1行は構造化JSONで最大8 KiB、ログ全体は1 MiBで世代ローテーションする。現世代と直前の世代だけを保持する。
- ログ書込みは診断のための処理であり、失敗してもCodexの終了処理や安全な実行禁止を妨げない。書込み不能は`diagnosticsUnavailable`として画面へ返す。

## 記録形式

各行には`version`、`at`（UTC）、`traceId`、`operation`、`stage`を含める。追加値は固定の安全な種類に限る。

| stage | 主な値 |
| --- | --- |
| `received` | 要求種別 |
| `rejected` | `errorCode` |
| `codex_started` | PIDなしの起動成功印、経過時間 |
| `rpc_sent` / `rpc_received` | RPC名、ID、モデル一覧のページ番号・件数 |
| `agent_message` | 本文ではなく文字数 |
| `cleanup_started` / `cleanup_signal` | 終了処理開始、TERM・KILLの送信結果と失敗時のerrno |
| `cleanup_leader_exit` | リーダープロセスの終了コード |
| `cleanup_group_check` | プロセス群の消滅確認結果。残存時はLinux `/proc`から状態別の件数と読取不能数、走査上限到達の有無 |
| `cleanup_failed` | 終了処理中の例外分類、OSエラー時のerrno |
| `terminal` | 状態、固定エラー分類、プロセス群消滅確認、経過時間 |

プロセス状態は件数のみで、PID、プロセス名、引数、パスは記録しない。`/proc`の走査には上限があり、同時に消えたプロセスや権限不足などで読み取れないプロセスもあるため、件数は終了の安全確認には使わない。Codexエラーの生文、標準エラー、プロンプト、応答本文、モデル名、作業パス、カーソルは保存しない。UIへ返す既存のエラー文もログには複製しない。

モデル一覧の取得後にプロセス群の終了を確認できない場合、一覧を利用可能にせず、`process-unconfirmed`の失敗として画面とログに返す。実行記録は従来どおり保持する。

## 会話本文の扱い

指示文・応答本文の追跡は、診断ログとは別の明示的な将来機能とする。既定保存はしない。追加する場合もユーザーが一回ごとに明示し、専用の`0600`保存領域、保持上限、削除UI、秘匿値を含み得ることの警告を設ける。本設計の原因特定は本文なしで成立させる。

## 失敗時の扱い

Hostが強制終了・電源断されると終端行は書けない。この場合は実行記録を残して後続操作を禁止する既存の安全策を優先する。次回、OS再起動が実行記録を安全に解除した時に、該当`traceId`が記録されていれば`abandoned_after_reboot`を追記する。

Host自体が起動しない場合はHostログを残せないため、Firefox側でNative Port切断と要求種別だけを一時記録することを後続課題とする。

## 確認条件

少なくとも、正常な複数ページ取得、RPCエラー、EOF、タイムアウト、入力検証拒否、ログ保存不能について、画面の`traceId`とJSONLの記録から直前の成功段階と終端理由を一意に確認できることを自動試験する。
