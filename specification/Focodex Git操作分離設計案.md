Focodex Git操作分離設計案
1. 基本方針
Codexにはソースコードの開発を担当させ、Gitの変更操作はFocodexが独立して管理する。

Focodexは、音声とタッチ操作によるFirefox拡張の反復開発を目的とする専用フロントエンドであり、汎用的なCodex操作環境を目指さない。

そのため、CodexにGitリポジトリの変更権限や外部へのpush権限を与える必要はない。

Git操作を分離することで、Codexが誤操作した場合でもGit履歴を保護し、プロジェクトの復旧手段を確保する。
2. 権限の分離
操作	Codex	Focodex Git機能
プロジェクト内ファイルの読み取り	許可	許可
プロジェクト内ファイルの編集・削除	許可	原則対象外
テスト・ビルド	許可	対象外
git status	許可	許可
git diff	許可	許可
git log	許可	許可
git add	禁止	許可
git commit	禁止	許可
git push	禁止	承認制
git reset / checkout	原則禁止	必要に応じて実装
プロジェクト外への書き込み	禁止	Git操作に必要な範囲のみ
外部ネットワーク通信	禁止	Git push等に必要な範囲のみ


Codexのpermission profileによって、通常リポジトリとworktreeのGit管理情報を変更できないようにする。外部ネットワーク通信も許可しない。

FocodexのGit機能は、Codexのサンドボックスとは別のNative Host処理として実装する。

CodexにGit操作のための追加権限を与えないことを原則とする。ここで保証するのは既存リポジトリの管理情報変更と外部通信を許可しないことであり、プロジェクト内の編集権限からGitコマンドそのものを全面禁止することではない。

なお、.git の書き込み禁止だけでは作業ツリーに影響するGitコマンドをすべて阻止できない。Git履歴の保護とGitコマンドの全面禁止は区別する。

Git管理機能はCodex App Serverを経由せず、Native HostからGitを直接操作する。

Git操作用Native Hostは、自由なシェルコマンドを受け付けず、事前定義された操作のみ実行する。
4. Git管理UI
タッチ操作を前提として、次の機能を用意する。
MVP
機能	内容
状態確認	変更ファイル一覧を表示
差分確認	変更内容を表示
ステージング	対象ファイルを選択してadd
コミット	メッセージを入力してcommit
Push	送信先・ブランチを確認して実行


コミットメッセージはFocodexの専用欄で保持し、fox-voice-editorからの受信バッファをユーザーが明示操作で全文置き換えできるようにする。

Git管理画面はFocodex内の独立したパネルとして実装する。
将来的な追加候補
- コミット履歴の表示
- 変更の取り消し
- 過去のコミットへの復旧
- ブランチ切り替え
- Pull
これらはMVPには含めず、必要になった段階で検討する。
5. CodexにGit操作を依頼した場合
例えば、ユーザーが次のように指示する。
変更をコミットしてGitHubにpushしておいて。

CodexにはGit変更権限がないため、直接実行できない。

想定する挙動は次のとおり。

MVP段階

CodexはGit操作を実行せず、ユーザーにFocodexのGit管理機能を利用するよう案内する。

ただし、Codexが必ず適切に案内するとは限らないため、権限制限は独立して強制する。

将来的な拡張

CodexからFocodexにGit操作を提案する仕組みを追加する。
ユーザー
「変更をpushしておいて」
        │
        ▼
      Codex
        │
        ├─ 変更内容を確認
        └─ Git操作を提案
                │
                ▼
           Focodex
                │
        ┌───────┴───────┐
        │               │
      拒否             承認
        │               │
      終了         Native Host
                        │
                    git push

この場合も、Gitを実行するのはCodexではなくFocodexとする。

Codexの通常の文章出力をコマンドとして解釈せず、明示的な操作要求を受け取る仕組みが必要になる。
6. セキュリティ上の要件
Codex側
- permission profileによるプロジェクト外への書き込み禁止
- プロジェクト外の読み取り禁止（例外は別途承認）
- .git の書き込み禁止
- 外部ネットワーク通信の禁止
- 権限拡大要求は原則拒否
- 制限を適用できない場合はCodexを起動しない
Git管理機能側
- 選択中のプロジェクトのみを操作対象とする
- 任意コマンドの実行は禁止
- Gitコマンドは引数配列で実行し、シェル経由の実行を避ける
- Git管理ディレクトリの実体パスを検証する
- Gitフックや外部ヘルパーによる意図しないコマンド実行を考慮する
- リポジトリ内の`.gitattributes`を、Codexが変更できる設定入力として検査する
- `.git/config`、worktreeの管理情報、include、filter、fsmonitor、外部diff、署名、SSH、認証ヘルパー、remoteの外部コマンド設定を許可規則なしには利用しない
- Push前にリモート・ブランチ・送信コミットを表示する
- 強制pushはMVPでは提供しない
- 操作結果はGitの実際の状態から確認する
なお、Git管理機能はCodexより強い権限を持つため、Native Host側で操作対象と引数を厳密に制限する。
残るリスク
Git履歴を保護しても、Codexは作業ツリー内のファイルを削除・変更できる。

また、プロジェクト内のスクリプトや`.gitattributes`を変更し、後から実行されるGit処理に影響を与える可能性がある。管理情報を書き換えられなくても、既存のフィルター設定と属性指定の組み合わせなどを通じて外部プログラムに到達し得るため、Git Hostはリポジトリを信頼せず検査する。

そのため、Git操作の分離だけで完全な安全性が保証されるわけではない。
7. 実装順序
段階	実装内容
第1段階	受信バッファを実装し、文章の受理と反映を分離する
第2段階	Git状態・差分表示、選択ファイルだけのステージ、ステージ内容の最終照合、Commitを実装する
第3段階	設定検査と認証方式を確定後、Fast-forward Pullと単一追跡ブランチへの通常Pushを実装する
第4段階	必要に応じてCodexからのGit操作提案に対応する


まずは第1段階を完了させ、CodexがGit履歴を変更できないことを検証する。

Git管理UIはその後に実装する。
8. 設計上の結論
Focodexでは、次の役割分担を採用する。

Codex：開発担当
- コードを調査する
- コードを変更する
- テストする
- 結果を報告する
Focodex：プロジェクト管理担当
- Gitの状態を管理する
- 変更を記録する
- GitHubへ送信する
- 必要に応じて変更を復旧する
ユーザー：最終判断
- 変更内容を確認する
- コミットを確定する
- Pushを承認する
この設計の目的
Codexが誤った変更を行っても、被害を原則として選択中のプロジェクトの作業領域に限定する。

Git履歴と外部リポジトリはCodexの直接操作から保護し、Focodexの専用機能を通じて管理する。

これにより、Codexには開発の自由を与えつつ、変更の記録と公開はユーザーの管理下に置く。

Focodexの用途である「音声とタッチによるFirefox拡張の反復開発」に適した、限定的な権限モデルを目指す。
