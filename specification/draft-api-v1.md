# 受信バッファ連携API v1

2026-10-22。ユーザーの条件付き実装推奨を受けた実装契約。

## 責務と境界

- fox-voice-editor：文章を作り、明示操作で送信する。
- Focodex：文章を受信バッファへ保存し、ユーザーの明示操作による入力欄への反映と実行を管理する。
- Native Host：許可されたOS操作だけを提供する。外部メッセージの転送先にはしない。
- Codex CLI：制限された環境で開発作業を行う。

連携先が増えても、用途別の専用APIと公開操作の一覧を維持する。初版は認証トークン・暗号化・汎用の外部コマンドAPIを追加しない。詳細な脅威と代替案は[連携検討](fox-voice-editor連携検討.md)を参照。

## 必須条件

1. Firefox提供の送信元IDとページURLを検証し、認証失敗では保存・通知・タブ起動を行わない。
2. 受信・個別削除・全件削除を背景で直列化する。文章は最大3件のFIFOで保存する。
3. 受理済みID、本文、受理日時を、直近100件・24時間を上限としてバッファと同じ保存レコードへ保持する。削除・FIFO押し出し後も上限内は保持する。
4. 受理通知の前に文章と受理済みIDを`storage.local`へ保存する。保存失敗時はバッファを変更せず`rejected`を返す。

## 公開する外部操作

許可元は`fox-voice-editor@foxbook.example`、ページは`moz-extension:`の`/editor.html`のみ。クエリ・フラグメント・ユーザー情報・ポート・ID欠落は拒否。URLの内部UUIDは固定しない。Firefoxの`externally_connectable`は未対応のため利用しない。

| type | 入力フィールド（共通でversion=1、requestId） | 応答 |
| --- | --- | --- |
| `focodex.buffer.receive` | `text` | `accepted` / `duplicate` / `rejected` |

入力は上記のフィールドだけを許可。要求IDはUUID形式、本文は空白だけを除き1〜20,000 UTF-16コード単位。改行や空白を変更しない。応答は`version`, `requestId`, `status`と定型`reason`だけとし、文章・設定・パスを返さない。新規保存は`accepted`、同一ID・同一本文の再送は`duplicate`、同一ID・異なる本文や検証失敗は`rejected`とする。応答を失った送信側は、同じIDと本文を明示操作で再送できる。状態照会APIは公開しない。24時間または100件の上限を越えたIDの再利用は防止しない。

認証後も短時間の大量要求を制限する。本文やエラーを無制限にログへ蓄積しない。

## 画面・保存

- 受信時に入力欄へ自動反映しない。折りたたみ可能な受信バッファから文章を選び、Codex指示文またはCommitメッセージ欄へ全文置き換えする。反映確認は表示しない。
- 反映前の文章は各入力欄ごとに独立して「元に戻す」で1回だけ復元できる。各入力欄が空でなければ「クリア」を表示し、クリアも同じUndo対象とする。
- 反映・削除は対象の`requestId`を指定して行い、表示順では特定しない。反映後も文章はバッファに保持する。反映だけでCodex・Gitを実行しない。
- Codex、モデル取得、すべてのGit操作の実行中は受信項目の反映・削除を無効化し、完了後に再有効化する。
- 第2段階の反映先はCodex指示文とCommitメッセージ欄である。外部APIは反映先を指定せず、どちらもFocodex内で明示選択する。追加質問への反映は未実装。
- 指示文の初期値は空であり、接続試験文の専用ボタンは提供しない。
- fox-voice-editorは送信先IDを端末内設定として保持する。新規送信は新しい要求IDを作る。応答を失った要求だけ、同じ送信先・要求ID・本文で明示再送できる。コピー機能と文章は維持する。

## 検証範囲

送信元認証の副作用ゼロ、並行受信、FIFO、同一ID再送、同一ID・異本文の拒否、FIFO押し出し後の重複検出、保存失敗、旧1件保留データの移行、背景再起動を模擬試験で確認する。Firefoxの実配送、画面操作、Split View／Surfaceタッチは別途実機検証する。ブラウザや端末の侵害、開発時の同ID拡張への差し替えはID認証の保証外。
