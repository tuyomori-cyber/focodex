# Focodex 仕様書 v0.1.3

- 文書種別：MVP実装仕様（改訂版）
- 改訂日：2026-10-21
- 状態：基本方針合意・技術検証項目あり

## 1. 目的

Focodexは、Firefox拡張の改修作業を、Surface Pro 4のfoxbook環境で**物理キーボードを使わず、タッチと音声入力で継続するためのCodexフロントエンド**である。

主な利用場面は、メインPC（Xubuntu等）で開発・準備したFirefox拡張をSurfaceで実機確認し、その場で見つけた不具合や改善点をCodexに修正させ、再確認すること。場所を変えても開発の続きを行えることを重視する。

**メインPCの代替や、Surface単体で開発工程をすべて完結させることは目指さない。** 環境構築、複雑なGit操作、競合解決、重大な障害対応などはメインPCまたはSSH操作に委ねる。便利機能は最小限とする。今回の仕様補足は、多機能化ではなく、MVPの操作・停止・変更管理を確実に成立させるために行う。

## 2. 想定環境と構成

- 対象端末：Surface Pro 4（Fedora + 改造Cage + Firefoxのfoxbook環境）。
- 通常操作：タッチのみ。物理キーボードは使用しない。
- Focodex：独立したFirefox拡張、独立したリポジトリ `focodex`。
- 音声入力・文章編集：独立したFirefox拡張 `fox-voice-editor`。
- 両拡張の配置：Firefox標準のSplit View等を利用。専用ワークスペース拡張は作らない。
- OS側との接続：Firefox Native Messagingを利用する。
- Codex制御：Native Host経由でCodex CLIを利用。`codex app-server`を有力候補として実装時に検証する。

```text
fox-voice-editor ──（拡張間メッセージ）──▶ Focodex（Firefox拡張）
                                              │
                                       Native Messaging
                                              │
                                              ▼
                                       Focodex Native Host
                                              │
                                       Codex CLI / app-server
                                              │
                                       登録済みプロジェクト
```

## 3. 基本操作フロー

1. Firefoxで開発対象の拡張を一時的に読み込み、実機で確認する。
2. fox-voice-editorで音声入力し、ブロック編集などで指示文を整える。
3. fox-voice-editorの送信ボタンからFocodexへ文章を渡す。
4. Focodexの入力欄で内容を確認し、ユーザーが明示的に実行する。
5. Codexが登録済みプロジェクトのソースを調査・修正する。
6. 実行中は控えめなアニメーションを表示し、必要な承認要求や追加質問にはユーザーが応答する。
7. 完了後は結果の要約を表示し、必要に応じて詳細を展開する。
8. 対象拡張を再読み込みし、実機で再確認する。必要なら繰り返す。
9. 作業を引き継ぐ場合はGitで変更をメインPC側へ受け渡す。

## 4. Focodex UI

### 4.1 基本画面

- 登録済みプロジェクトの選択欄。
- Codexから取得した候補のモデル選択欄と一覧再取得操作。モデル未選択では実行しない。
- 選択したモデルを今回の実行に適用し、Codexの既存設定ファイルは変更しない。選択は端末内でプロジェクトごとに保持し、次回の一覧に存在する場合のみ復元する。
- モデルが拒否された場合はエラーを表示し、指示文を保持したままFirefox内で別モデルを選んで再送できる。候補一覧への掲載を実行成功の保証とは扱わず、無断で別モデルに切り替えない。
- 指示文の入力・確認欄、実行ボタン。
- Codexの直近の実行結果（通常は要約）。
- 過去の結果を折りたたんで参照できる表示。
- 必要最小限のGit操作。
- Firefox拡張の再読み込み導線。

### 4.2 実行中

- 小さな点の明滅など、控えめなアニメーションを表示する。
- 実行中の逐次ログや擬似的な進捗率は通常表示しない。
- 停止ボタンを設け、「停止要求中」と「停止確認済み」を区別する。停止要求の送信だけで停止済みと表示しない。
- Codexから承認要求が来た場合は、アニメーションに代えて対象の操作・変更内容・要求権限と承認／拒否操作を表示する。
- Codexから追加質問が来た場合は、質問本文と、選択肢または自由文の回答欄を表示する。自由文はタッチ・音声入力で用意できることとし、fox-voice-editorから受け取った文章を回答欄へ反映する操作を用意する。
- 追加質問への回答はユーザーの明示操作で送信する。承認待ち・回答待ちでも停止できる。
- 停止開始後は承認・回答を送信しない。完了・中断などで失効した要求には回答できないようにする。

### 4.3 実行結果

- 通常は短い要約を表示する。
- タップで詳細を展開できる。
- 詳細にはCodexの回答全文を保持し、取得できる範囲で変更内容、対象ファイル、テスト結果、エラー情報を表示する。
- 実施していないテストを成功と表示しない。
- 過去の結果も折りたたみ表示を基本とする。

## 5. fox-voice-editorとの連携

- 両者は独立した拡張として開発・配布する。
- fox-voice-editorのプレビュー／コピー付近に送信ボタンを設ける想定。
- 送信先はfox-voice-editor側で設定可能とする。
- Focodexは受け取った文章を指示文または追加質問の回答の下書きとして扱い、**受信と同時にCodexの実行や回答の送信を行わない**。
- 対象の入力欄が空の場合は受信文を反映する。既存の下書きがある場合は自動で上書きせず、受信文を一時保持し、ユーザーが「置き換え」または「受信文を破棄」を選ぶ。
- 未処理の受信文がある間は後続の受信を拒否し、送信元に再送が必要なことを返す。受信文を無言で上書きしない。
- 実行中も次の指示文を受信できるが、自動実行・実行キューへの追加・実行中処理への割り込みは行わない。追加質問への反映はユーザーが対象を明示して行い、回答欄にも同じ下書き保護を適用する。
- 送信元には受信成功・拒否・エラーを返す。受信成功はCodexでの実行や回答送信の完了を意味しない。
- 拡張間メッセージングを候補とし、送信元の識別・検証を行う。
- Focodex側で本格的な音声認識やブロック編集機能を重複実装しない。

## 6. プロジェクト選択

- MVPではNative Host側の設定ファイルに登録したプロジェクトから選択する。
- 登録・削除はメインPCまたはSSHで設定ファイルを編集して行う。Surface上のファイルブラウザは作らない。
- 選択したプロジェクトのディレクトリをCodexの作業ルートとする。
- 将来的にはFirefoxの一時読み込み拡張の読み込み元を利用できると便利だが、標準WebExtensions APIから他拡張の絶対パスを取得できる前提にはしない。実装時に実現性を検証し、複雑なら見送る。

## 7. セッションとキャンセル

### 7.1 単一セッション・同時実行1件

- MVPではFocodexの操作タブを1つとし、アクティブなCodexセッションは1つ、同時実行は1件とする。並列実行・実行キュー・複数セッションの管理画面は作らない。
- 重複したタブからは実行できないようにし、Native Host側でも同時実行を防ぐ。
- 実行中・承認待ち・回答待ち・停止要求中は、新たな実行、プロジェクト切り替え、FocodexのGit変更操作（ステージング・commit・pull・push）を受け付けない。
- プロジェクト切り替え時に別プロジェクトの会話を継続利用しない。履歴を保持したまま、切り替え先の会話を再開するか新規に開始する。読み取り専用の過去履歴表示は同時実行に含めない。

### 7.2 停止処理の状態管理

- 実行状態は「待機」「実行中」「承認待ち」「回答待ち」「停止要求中」「完了」「停止済み」「エラー」を区別する。
- Focodexのタブを閉じた場合、**実行中のCodex処理はキャンセル扱い**とする。誤タップであっても同様。タブの再読み込みやFirefox終了による接続断も停止対象とする。
- ユーザーが停止ボタンを押した場合もキャンセルする。停止要求は重複送信で別の処理を起こさない。
- 停止要求後は「停止要求中」とし、Codexの中断完了と、その実行に属する子プロセスの終了を確認して「停止済み」とする。完了と停止が競合した場合は、確認した実際の終了状態を記録する。
- 通常の停止が所定時間内に完了しない場合は、Hostが管理する当該実行のプロセス群を終了する。待機時間と終了手順は最初の技術検証で決定し、実装時に文書化する。他のCodex利用のプロセスは対象にしない。
- 終了確認ができない場合はエラーとして扱い、停止済みとは表示しない。終了を確認できるまで新たな実行やGit変更操作を許可しない。
- Native Messaging切断時はUIからの停止メッセージに依存せず、Host側で停止・後片付けを行う。Host異常終了時の残留防止も検証する。
- キャンセル時に既存のファイル変更を自動ロールバックしない。再表示時には中断・異常終了の状態と、変更が残り得ることを示す。
- Surfaceのスリープ・復帰時は接続状態を確認し、終了状態が不明なまま実行を自動再送しない。
- タブ誤閉鎖対策はFirefox標準の「タブをピン留め」を利用可能。Focodex独自のタブ固定機能はMVP対象外。

### 7.3 会話履歴

- 会話履歴と完了済みの結果は端末ごとに管理する。履歴はプロジェクトと対応付け、利用可能なインターフェースに合わせて同じ端末内のCodexセッションを再開する。
- Gitで受け渡す対象はプロジェクトの変更であり、会話履歴・Codexセッションの端末間同期は実装しない。
- メインPCへ判断経緯を渡す必要がある場合は、ユーザーの指示によりリポジトリ内の文書に残す。会話同期や自動エクスポート機能は追加しない。
- 履歴の保存場所・保持上限・保存タイミングは採用するCodexインターフェースの確認後に決める。タブを閉じても完了済み履歴を保持し、中断を成功として記録しない。

## 8. Firefox拡張の再読み込み

- Codex修正後、対象の一時読み込みFirefox拡張を再読み込みして実機確認できることを重要視する。
- **Focodexからワンタップで再読み込みする方法を実装時に検証する。**
- 通常のWebExtensions APIで他拡張を直接再読み込みできるとは想定しない。Firefoxの開発者向けデバッグ機構等の利用可能性を検証する。
- 自動再読み込みが困難なら、`about:debugging#/runtime/this-firefox` を開いて手動再読み込みできる導線を用意する。
- 再読み込み自動化の未実現を理由にMVP全体を停止しない。

## 9. Git操作（最小限）

- 目的はメインPCとSurfaceの間で同じ開発作業を引き継ぐこと。
- 原則として両端末で**同じブランチ**を利用し、Surface専用ブランチ管理機能は設けない。
- MVP対象：`git status`、`git pull --ff-only`、変更確認とファイル単位の選択的ステージング、`git commit`、`git push`。
- ステージングはファイル単位とし、差分の一部分（行・ハンク単位）の選択はMVP対象外とする。削除や名前変更を含む変更を確認できること。
- 既にステージ済みの変更を勝手に解除しない。コミット直前には、今回の選択分だけでなく、コミットに含まれるステージ済み変更全体を提示し、ユーザーの明示操作でコミットする。
- 表示した差分の確認後にファイルやステージ済み内容が変わった場合は、そのままコミットせず再確認を求める。
- コミットメッセージはユーザーが指定する。
- 変更ファイルを確認せずに無条件で `git add -A` しない。
- pull不可・push拒否・競合等が発生したらエラーを示して停止する。自動マージ・競合解決・ブランチ管理は実装しない。
- GitHub認証はSurface側で事前設定し、Focodex自体は認証情報を管理しない。
- 自動pull／自動pushは行わず、ユーザーの明示的操作とする。
- `pull`や`fetch`も外部通信を伴うため、第10節の「その他の外部通信」に従い、接続先・取得内容の確認方法を決めるまで実行不可とする。ローカルのGit操作でもフックや外部コマンドによる逸脱を防ぐ設計を要する。
- 基本の受け渡し手順は、移動元でcommit・pushし、移動先で編集前にpullする。履歴が分岐した場合の解消はメインPCまたはSSHで行う。
- Git操作は直列化し、Git変更操作中はCodexの新規実行とプロジェクト切り替えを受け付けない。

## 10. Focodexの権限方針

Focodexはタッチ端末での反復開発に必要な操作だけを提供する。基本原則は「選択プロジェクトの中では自由に開発できる。それ以外には原則触れない」。Codex CLIの汎用的な権限昇格画面は提供しない。

| 操作 | 権限 | 承認 |
| --- | --- | --- |
| 選択プロジェクト内の読み取り・書き込み | 許可 | 不要 |
| プロジェクト外の読み取り | 原則禁止 | MVPでは承認経路を設けない |
| プロジェクト外の書き込み | 禁止 | 承認不可 |
| プロジェクト内のGit操作 | 許可 | 原則不要 |
| Git push | 条件付き許可 | 接続先・ブランチ等を示して今回だけ承認 |
| その他の外部通信 | 原則禁止 | 用途別に設計・検証するまで不可 |
| 権限昇格 | 禁止 | 承認不可 |

- Firefox拡張からOS操作を行う経路はNative Messagingに限定する。Native Hostは操作、プロジェクトID、パス、要求IDを検証し、汎用コマンド実行APIを設けない。
- プロジェクト境界はパスの文字列比較だけで判断せず、シンボリックリンクや実際のアクセス先も考慮する。作業ディレクトリの指定だけを隔離とみなさない。
- プロジェクト内の通常作業にはCodex標準の権限機構を使い、Codexの既存設定ファイルは変更しない。管理者が強制した制約は緩和しない。Codexの有効な設定が必要条件を満たさない場合は実行を止める。現行実装は従来の`workspaceWrite`を使用中。
- Codexからの一般的なコマンド承認・ファイル変更承認は、表示だけで安全性を判定できないため承認不可とする。外部読み取りの承認UIはMVPで実装しない。Git pushを実装する際は専用操作と明示的な承認を設ける。情報不足、失効、ID不一致は拒否する。
- 従来の`workspaceWrite`ではプロジェクト外の読み取りを一律に遮断できない。次の開発課題として、Codex標準のベータ版permission profileを採用できるか、使用中のCLI・app-server・Xubuntuで検証する。まず「プロジェクト内の読み書きは許可、外部のユーザーファイルは原則読み取り禁止、コマンドの外部通信は禁止」を確認する。実行に必要な最小限のシステムファイルは例外になり得る。profileは従来のsandbox指定と併用しない。検証を終えるまで読み取り境界を達成済みと表示しない。
- Git操作はNative Hostの専用操作として設計する。`git push`はCodexの汎用コマンド承認で代替せず、接続先・ブランチ・送信内容を確認して明示操作を求める。`pull`・`fetch`の通信条件とローカルGitフックの扱いも別途定める。Git操作は未実装なので現行版ではpush・pullとも不可。
- Codexの認証・設定へのランタイム自身のアクセスと、Codexがユーザー指示に基づいて行うファイル操作を区別して検証する。外部通信はモデル応答に必要なCodex通信を除き、用途別の設計が終わるまで許可しない。
- Native Hostの切断時に子プロセスが残留しないようにする。

## 11. MVP対象外

- 新規プロジェクト作成、汎用IDE、コードエディタ、ファイルマネージャ。
- Gitの高度な管理、ブランチ切り替え、競合解決、行・ハンク単位のステージング。
- 会話履歴・Codexセッションの端末間同期。
- 複数セッションの同時管理、並列実行、実行キュー。
- Focodex独自の権限設定画面。
- Firefoxの独自ワークスペース／ウィンドウ管理。
- Codexのバックグラウンド常駐や、タブを閉じた後の実行継続。
- 自動ビルド、署名、公開、リリース管理の一式。
- 複雑な開発環境構築・障害復旧のSurface単独完結。

## 12. 実装時の優先検証事項

以下の順番で進める。**最初にNative Messaging経由でCodexと一往復できることを確認し、成立するまで本格的なUI・Git操作の実装を広げない。**

1. Firefoxの最小限の拡張ページ → `runtime.connectNative()` → Focodex Native Host → `codex app-server` 等の経路で、登録済みプロジェクトに指示を1件送り、応答本文と終了状態をFirefoxへ返せることを確認する。採用CLIバージョンと事前認証・設定条件を記録し、第10節の権限方針に従って検証する。
2. 同じ経路で承認要求・追加質問への回答・停止を確認する。停止要求中と停止完了を区別し、タブ閉鎖・接続断・Host異常終了でプロセスが残らないことを確認する。停止待機時間と強制終了手順を確定する。
3. Surface実機でSplit View、fox-voice-editorからの送信と下書き保護、承認・質問回答・停止・結果展開、対象拡張の手動再読み込みまでをタッチだけで通す。拡張間メッセージの形式と送信元検証も確認する。
4. 上記の成立後、端末内の履歴保存・セッション再開と、ファイル単位のGit操作・端末間の変更受け渡しを確認する。
5. ワンタップの拡張再読み込みを検証する。困難なら `about:debugging` の手動導線を採用し、MVP全体を停止しない。
6. 一時読み込み拡張の読み込み元ディレクトリの特定は任意・優先度低とし、MVP成立の条件にしない。

## 13. MVPの完成条件

- 登録済みプロジェクトとモデルをFirefox内で選択でき、モデル拒否時も別モデルを選び直して再試行できる。
- fox-voice-editorから文章を受け取り、ユーザーの明示操作でCodexへ送れる。
- 単一セッション・同時実行1件を守り、複数タブからの重複実行や、実行中のプロジェクト切り替え・Git変更操作を防げる。
- Codexの実行・停止・必要な承認・追加質問への回答をタッチと音声入力で行える。
- 文章受信で既存の下書きを自動上書きせず、受信だけで実行・回答送信しない。
- 実行中は簡潔なアニメーションを表示し、結果は要約／詳細を切り替えられる。
- 修正したFirefox拡張を、少なくともタッチ操作で再読み込みして確認できる。
- ファイル単位で変更を選択してステージングし、コミット対象全体を確認した上でGitによる変更の受け渡しができる。
- 会話履歴を端末ごとに保持し、端末間同期を必要とせず利用できる。
- 第10節のFocodex権限方針を強制し、許可対象だけを要求単位で承認できる。
- 停止要求中と停止確認済みを区別し、タブを閉じた際のキャンセルとプロセス終了が適切に機能する。終了不明時に新たな実行を開始しない。
