# Focodex 仕様書 v0.2.1

- 文書バージョン：0.2.1
- 作成日：2026-10-31
- 状態：現行実装ベース。v0.2.0を土台に終了確認・診断と実機検証結果を反映
- 対象：Firefox拡張、Native Messaging Host、Codex app-server、限定Git操作、専用SSH Agent

## 1. 目的と境界

FocodexはFirefoxからNative Messaging経由でCodexへ指示を送り、応答・終了状態を表示する。登録済みワークスペース内のGitリポジトリに限り、状態確認、差分確認、選択ファイルのstage／commit、fetch／pull／pushを段階的な確認付きで扱う。

任意シェル、任意パス、任意Git引数、任意ネットワーク宛先は受け付けない。Codex実行とGit書込みは同時に行わず、停止・異常終了・不確定な後始末では安全側に停止する。画面、タブ、拡張およびツールバー上の表示名称は「Focodex」とする。拡張の内部バージョンと識別子は表示名称とは別に管理する。

## 3. ワークスペースとCodex

設定は`~/.config/focodex/config.json`に置く。ワークスペースは明示登録したリポジトリだけを含み、検出ルートや親ディレクトリ自体にCodex権限を与えない。単独リポジトリのGit操作は、Codexの永続権限対象へ追加しない。

Codex実行ではモデル一覧を同一接続で取得し、選択モデル・許可対象・理由を画面で確認する。汎用のファイル変更・コマンド実行承認は許可せず、追加質問だけを明示回答する。停止後は専用プロセス群の終了確認まで次の実行を開始しない。

### 3.1 終了確認と安全停止

各モデル一覧取得・Codex実行は専用セッションのプロセスグループで開始する。正常完了、停止、時間切れ、接続断などの後始末では対象グループにSIGTERMを送り、最大約1秒待って残っていればSIGKILLを試みる。リーダー終了の回収後、`killpg(pgid, 0)`による消滅確認を最大1秒、50ms間隔で再試行する。スケジューリング等により実経過時間は多少前後する。

`ProcessLookupError`のみをプロセスグループ消滅の確認成功とし、`PermissionError`を含むOSエラーや期限内に消滅を確認できない場合は終了未確認とする。`/proc`の状態別件数・読取不能件数は診断情報であり、終了の安全判定には使わない。モデル一覧を取得できても終了未確認なら一覧を成功として提供しない。

同じHost設定を使う操作は共有ロックと実行記録で排他する。起動前に実行記録を保存し、プロセスグループの消滅確認と記録の照合が成功した場合にのみ削除する。終了未確認・Host異常終了後は記録を保持し、同じ設定のHostから競合するCodex・Git操作と設定変更を拒否する。正常な記録はOS再起動によるboot IDの変化を確認した場合にも解除できるが、Firefox／Hostの再起動やPIDが見当たらないことだけでは解除しない。破損した記録は自動解除せず、手動削除して迂回しない。

この確認の対象は元のプロセスグループであり、別グループ・別セッションに離脱した子孫の終了までは保証しない。HostがSIGKILL等で強制終了した場合も、子孫が残る可能性がある。同一設定外のHostや外部の手動操作は共有排他の対象外である。詳細は[終了経路・プロセス管理調査](../docs/終了経路・プロセス管理調査.md)を参照する。

### 3.2 操作診断

モデル一覧取得またはCodex実行の要求には原因調査用の`traceId`を付け、画面に表示する。Native Hostは要求受信、Codex起動、app-server RPC、終了処理などを内容非保存の診断ログへ記録する。`cleanup_group_check`には終了確認結果、確認回数`attempts`、確認開始からの実経過ミリ秒`waitedMs`を記録し、残存時は可能な範囲で状態別件数等を付ける。ログ記録自体は安全判定を変えない。

指示文、応答本文、モデル名、生カーソル、Codexの生エラー本文、PID、プロセス名、引数は操作診断ログに記録しない。ログの保存失敗やHost起動前の失敗、切断・強制終了時には、記録または終端行が残らない場合がある。保存場所・保持上限・失敗時の扱いは[操作診断トレース設計](操作診断トレース設計.md)を正とする。

## 4. GitとSSH

Git書込みは確認した対象・スナップショット・選択ファイルだけに限定する。hook、署名、継承環境、進行中のGit操作、競合・sparse／split index、想定外の状態は拒否する。リモート操作は現在のブランチの単一upstream、明示的な`ssh://` URL、既知鍵、専用SSH Agentを検証してから行う。force push、任意リモート、通常の`SSH_AUTH_SOCK`の流用は行わない。

専用Agentは`FOCODEX_REMOTE_AGENT`で指定された所有者限定Unixソケットだけを受理する。固定設定・固定鍵・Secret Serviceの値を検証し、画面・診断・永続ログへ秘密鍵、パスフレーズ、公開鍵、リモートURLを出力しない。導入と復元の手順は[専用Agent運用文書](../docs/dedicated-ssh-agent-operations.md)を正本とする。

## 5. fox-voice-editor連携

`focodex.buffer.receive`を受け、文章を最大3件のFIFO受信バッファへ保存する。受信だけでは入力欄変更・Codex実行を行わない。同一request ID・同一本文は重複追加せず、同一ID・異なる本文は拒否する。横断契約の正本は[`IF-VE-FD-001`／`002`](../../foxbook/docs/interfaces/fox-voice-editor--focodex.md)である。
