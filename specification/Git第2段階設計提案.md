# Git第2段階：承認済み設計と実装

2026-10-22。ユーザーが②設定規則・③固定tree方式を承認し、第2段階を実装済み。①終了未確認時の禁止をGit処理にも適用した。Firefox・Surface実機での操作確認は未実施。

## 対象と現状

- 第2段階はStatus、選択ファイルのステージ、差分確認、Commit、受信バッファからCommit欄への明示反映だけ。
- Pull・Push・fetch、任意コマンド・任意引数、ブランチ管理、競合解決、amend、ハンク単位の操作は提供しない。
- 既存のステージ済み変更は解除しない。今回選択したものを含む、ステージ済み全体を最終確認する。
- 現行実装はStatus・差分表示・ファイル選択・ステージ・固定treeの最終確認・Commit・Commit欄への反映。Git操作対象を開始プロジェクトと独立に選択する。

## ① 実行状態とロック（今回の修正）

同じHost設定を使う操作全体を既存のflockで直列化し、安全な待機状態は独立した`config.execution.json`で管理する。

1. ロック取得後、永続記録がないことを検査する。
2. Codexのプロセスを生成する**前に**ランダムな実行トークン、Linux boot ID、対象ルート、開始時刻を原子的に保存し、ファイルと親ディレクトリをfsyncする。モデル取得にも適用する。
3. 専用プロセス群の消滅を確認し、記録の所有トークンが一致した場合だけ記録を削除する。
4. 終了確認失敗・後片付けの例外・HostのSIGKILL・起動中の障害では記録を残す。OSロックが解放されても、別Hostは後続のCodex・Git操作・設定変更を拒否する。
5. PIDやリーダープロセスの不在だけでは解除しない。正常な記録はOS再起動によるboot IDの変化を照合したときにも解除できる。破損記録・boot ID取得失敗は拒否し、自動修復しない。

起動前保存とプロセス生成の間で障害が起きた場合も、保守的に禁止を維持する。Firefox・Hostの再起動だけでは解除しない。記録を手動削除する迂回手順は提供しない。

現行の正常終了確認は既存の専用プロセス群を対象とする。別セッションへ離脱する子孫までの封じ込めはプロセス群だけでは保証できず、cgroup等による包含は未実装。Host異常終了後はプロセス探索で解除せず再起動確認を使う。

排他と永続記録の共有範囲は**同じHost設定ファイル**。異なる設定で同じリポジトリを二重登録しても同じロックになる保証はなく、第2段階では単一の設定で運用する。Git変更操作も共通の待機確認を経由し、子プロセスの終了と結果確認までロックを保持する。

## ② 初版のGit実行規則（承認・実装済み）

### 公開操作と対象

Hostは操作名、登録済みのGit対象ID、ファイル一覧、確認トークン、コミットメッセージだけを受け取る。パスはHostが取得した変更一覧にあるファイル単位で照合する。引数配列はHostが固定生成し、シェルや外部拡張からのGit呼び出しは提供しない。

- ステージは一時インデックス上で`git add -A -- <選択したliteral pathspecだけ>`を実行し、存在する選択パスだけに`git add --renormalize`を適用して内容を再計算する。選択外のインデックス項目が変わっていないことと再取得した作業状態を照合し、Git標準のindex.lock・rename・fsyncで実インデックスへ反映する。一時インデックスへコピーした際の時刻変更で、Gitのstatキャッシュが同サイズの編集を見落とす問題を避ける。ディレクトリ・ワイルドカード・`.`は受け付けない。名前変更は移動前後のパスを1組として示し、両方を選択対象に含める。
- 通常ファイルの追加・変更・削除・名前変更を初版の対象とする。未解決競合、merge/rebase/cherry-pick等の進行中、detached HEAD、submodule/gitlink、sparse/split index、特殊ファイルと安全性を確認できないシンボリックリンク経路は拒否する。
- 通常リポジトリとworktreeの管理情報・実体パスを検証する。Git対象は開始プロジェクトとは別に画面で明示し、初版は選択ワークスペース内の登録済み1リポジトリに限定する。

### 設定の扱い

| 項目 | 初版の方式 |
| --- | --- |
| フック | 全操作で`core.hooksPath=/dev/null`。Commit前後だけでなく`reference-transaction`等も無効化する。 |
| 署名 | `commit.gpgSign=false`と`--no-gpg-sign`。署名プログラムを起動せず、署名付きCommitは提供しない。 |
| filter / LFS | `filter.*`設定とfilter属性がある対象は拒否する。既存設定を編集して解除しない。 |
| include / includeIf | `--no-includes`で元の設定を検査し、設定があれば拒否する。include先を読んでから判定する方式は使わない。worktree設定も同じ扱い。 |
| 外部diff / textconv / fsmonitor | 固定オプションで無効化し、それらを要求するリポジトリ設定は拒否する。 |
| 属性 | システム・ユーザー属性は無効化。作業ツリーとステージ済みの`.gitattributes`、`.git/info/attributes`を検査する。初版はGit内蔵の`text`・`text=auto`・`eol=lf/crlf`・単純な`diff`/`binary`とその解除指定だけを許可。独自マクロ、filter、外部diffドライバー、working-tree-encoding、ident、未知の指定は拒否する。 |
| 改行・変換 | `core.autocrlf=false`を固定し、上で許可した属性だけをGit標準で適用する。確認画面には変換後のステージ済み内容を表示する。 |
| SSH / 認証 / remote | 通信操作を一切呼ばない。SSH・認証ヘルパー・remote外部コマンド設定は初版では拒否する。通常のremote URL・追跡ブランチ名は非実行の登録データとして保持できる。 |
| 環境 | 継承の削除方式から許可リスト方式へ変更。固定PATH・ロケール・信頼したHOME等のみを渡す。親の`GIT_*`、`LD_*`、SSH・Askpass・認証・proxy・設定注入変数は継承しない。必要な`GIT_CONFIG_*`、`GIT_ATTR_NOSYSTEM`、一時`GIT_INDEX_FILE`等はHostが固定生成する。 |
| 作者名・メール | user.name/emailだけをincludeなしで明示的に取得して固定し、確認画面にも表示する。他のグローバル・システム設定は実行時に継承しない。不足時は停止し、外部で設定してもらう。 |
| その他の設定 | リポジトリ形式・検証済みworktree配置、作者情報、通常のremote/branchデータ等の限定した許可リストを実装する。未知の設定、外部object alternates、replace/grafts等でオブジェクト解釈や配置を変える構成は拒否する。 |

拒否理由は画面に示す。ユーザー設定を自動変更せず、拒否された機能のために許可範囲を広げるUIは作らない。設定・属性は操作前と最終確認時に再検査する。

Status・差分表示も同じ設定・属性検査経路を使う。初版のCommitは表示可能なUTF-8テキストに限定し、バイナリ・表示上限超過・非対応の構成は確認済みにしない。実インデックスはv2/v3のみ対応し、通常ファイルは2 MB、インデックスは16 MB、変更一覧は100件、Git出力・差分合計は約250 KBを上限とする。管理情報と属性走査にも上限を設け、超過時は処理しない。

## ③ Commit方式の比較と採用方式

| 方式 | 内容一致と競合 | 評価 |
| --- | --- | --- |
| インデックス再検証後に通常の`git commit` | 検証とgit commitによるインデックス取得の間に変更可能。後からCommit内容を検査しても誤った履歴は既に記録される。 | 単独では採用しない。 |
| 一時インデックスから通常の`git commit` | 対象は固定できるが、親・対象ブランチの確認と更新の関係は別途扱う必要がある。 | 比較案。 |
| **固定tree＋`commit-tree`＋旧OID指定の`update-ref`** | 表示とCommitに同じtreeを使用する。親と更新先の完全なブランチ名も固定し、旧OIDが変わっていれば参照更新を拒否できる。 | **推奨。Git標準コマンドで構成する。** |

採用方式の手順：

1. 選択ファイルだけを一時インデックスでステージ・検査してから実インデックスへ反映する。以前からのステージ済み変更は残す。
2. 実インデックスのコピーに`GIT_INDEX_FILE`を指定して`git write-tree`を実行し、全ステージ内容のtree OIDを取得する。確認画面は、その固定treeと固定した親Commitの差分から生成する。現在のインデックスを都度読んだ差分を確認済みとして扱わない。
3. Hostがリポジトリ実体、Git管理情報、完全なブランチ名、親OID、tree OID、設定・属性・作業ファイルの確認値、メッセージ・作者をHost内の15分有効・一回限りの確認トークンへ結び付ける。生のOIDや任意refはブラウザから受け付けない。
4. ユーザーのCommit操作後に共有ロックを取り、終了未確認記録がないことを確認する。短時間だけ実インデックスの`index.lock`を排他的に予約し、他の通常のGitステージ・checkoutを競合させない。人が画面を確認している間は保持しない。
5. ロック中の実インデックスをHost専用の一時インデックスへコピーし、`GIT_INDEX_FILE`をHostが指定して`write-tree`を実行する。通常インデックスと確認tree、HEAD/対象ref、設定・属性、表示対象の作業ファイルを再照合する。異なればCommitせず再確認する。一時インデックスを実インデックスへ戻す操作はしない。
6. `git commit-tree <確認tree> -p <確認親> --no-gpg-sign -F -`で固定した内容・親・メッセージのCommitを作り、tree・親・メッセージを実オブジェクトから照合する。初回Commitは親なしを別条件として扱う。
7. `git update-ref --no-deref <確認したrefs/heads/…> <新OID> <確認した旧OID>`で、**画面で確認したブランチだけ**を条件付き更新する。HEADを実行時に追い直して別ブランチへ更新しない。参照ロックとreflogの処理はGitに任せる。初回Commitは「参照が存在しない」を期待値にする。
8. 成功後にCommitと参照・実インデックス・作業ツリーを再取得し、結果を表示する。実インデックスを自動resetせず、別の変更も消さない。子プロセス終了・結果確認まで共有ロックを保持する。

更新前に対象ブランチが進んだ場合は、Gitの旧OID照合で更新せず再確認へ戻る。作成済みでも参照されなかったCommitオブジェクトは履歴への記録成功と扱わず、通常のGit GCへ任せる。失敗後の再送やロールバックは自動実行しない。

固定treeにより、最終照合後に外部から作業ファイルが編集されても、その内容が今回のCommitへ混入しない。通常Gitが尊重するロックで実インデックスを保護し、更新先は固定refと旧OID照合で保護する。ただし外部の任意のファイル書き込みを全停止する保証ではない。HEADが外部で切り替わっても更新先を追従させず、結果には確認したブランチを明示する。最終検査で判明した切替・外部変更は再確認へ戻す。Git管理ファイルを直接改変する外部プログラムまでの完全な原子性は保証しない。

HostによるHEAD.lockの自前保持は採用しない。Git 2.43.0のupdate-ref自身の処理と競合することを一時リポジトリで確認した。tree・親・対象refを固定する保証と、外部操作を完全に禁止する保証を混同しない。

Git操作全体を起動前の永続記録で囲み、すべてのGit子プロセス群の終了と結果確認後にだけ削除する。時間切れ・出力超過・シグナル終了・終了確認の例外・結果検証失敗は記録を残して禁止する。Hostの設定・実行記録が編集対象内に置かれている場合も拒否する。Host異常終了後に残るindex.lockは自動削除しない。Commitが既に記録されている可能性がある場合は、自動再送や自動ロールバックをしない。

## 実装時の受け入れ条件

- 選択外ファイルが追加ステージされず、既存のステージ済み内容も消えない。名前変更・削除・初回Commitを扱える。
- 確認treeとCommitのtreeが一致し、親・メッセージ・対象refも確認内容と一致する。
- 確認後の実インデックス・HEAD/対象ref・属性・作業ファイル変更で再確認する。旧OID不一致で参照を更新しない。
- 外部フック・署名・フィルター・ヘルパーの検出用プログラムが起動されず、通信操作が呼ばれない。
- Host強制終了、時間切れ、出力超過、Commit作成後からref更新までの各障害で、成功を誤表示せず、未知のまま再実行しない。
- Commit欄への反映・Undo・クリアだけでGitが実行されず、反映先のUndoが指示文と独立している。

## 根拠と事前検証

- [git-add](https://git-scm.com/docs/git-add)：選択パスのステージと`--renormalize`による強制再計算。
- [git-write-tree](https://git-scm.com/docs/git-write-tree)：インデックスからtreeオブジェクトを生成する。
- [git-commit-tree](https://git-scm.com/docs/git-commit-tree)：指定treeと親からCommitオブジェクトを作成する。
- [git-update-ref 2.43.0](https://git-scm.com/docs/git-update-ref/2.43.0)：旧OIDを期待値として参照を更新する。
- [gitの環境変数](https://git-scm.com/docs/git/2.43.0)、[設定](https://git-scm.com/docs/git-config/2.43.0)、[属性](https://git-scm.com/docs/gitattributes)。

ローカルGit 2.43.0の一時リポジトリで、確認後にインデックスを変えても固定treeのCommit内容が変わらないこと、一時インデックスで変更を検出できること、index.lockによるadd拒否、旧OID不一致のref更新拒否を確認済み。この事前確認に加え、Hostの長さ付きJSON経路で実Gitの一時リポジトリを操作する試験と、画面ロジック試験を追加した。結果は[検証記録](../docs/verification.md)を参照。
