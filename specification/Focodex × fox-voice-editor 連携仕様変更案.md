Focodex × fox-voice-editor 連携仕様変更案
2026年10月22日
1. 変更の目的
fox-voice-editorからFocodexへの文章連携を、従来の「指示文欄へ直接反映する方式」から、Focodex内の受信バッファを経由する方式へ変更する。

今回の変更は、今後追加するGit操作機能への対応と、拡張間通信の安全性・独立性を高めることを目的とする。

基本方針は以下のとおり。
- 文章の作成・編集はfox-voice-editorに一本化する。
- Focodexは文章を受信・保持し、ユーザーが選択した入力欄へ反映する。
- 外部拡張から入力欄を直接変更できないようにする。
- CodexおよびGitの実行は、Focodex内での明示操作に限定する。
- Codexには、既存リポジトリの管理情報変更と外部通信を許可しない。Gitの変更操作はFocodexの専用UIから提供する。

3. 受信バッファ仕様
3.1 基本仕様
項目	仕様
最大保持件数	3件
保存方式	FIFO（先入れ先出し）
保存先	browser.storage.local
受信時の動作	バッファに追加するだけ
入力欄への自動反映	しない
バッファからの反映	ユーザーが明示操作
反映方式	全文置き換え
追記・挿入	実装しない
反映後のデータ	バッファに保持
個別削除	可能
全件削除	可能


3.2 FIFO動作
バッファが3件に達した状態で新しい文章を受信した場合、最も古い文章を削除する。
初期状態
[A] [B] [C]

新規受信 D
    ↓
[B] [C] [D]

新規受信 E
    ↓
[C] [D] [E]

ユーザーによる確認操作は要求しない。

受信済みIDはバッファとは別に、直近100件・24時間を上限として保存する。個別削除、全件削除、FIFOによる押し出し後も、この期間内はIDを保持する。

送信側が応答を受け取れなかった場合は、同じ`requestId`と同じ本文を再送する。受理済みの同一ID・同一本文は追加せず`duplicate`を返す。同一IDで本文が異なる場合は保存せず`rejected`を返す。

同時受信時は処理を直列化し、保存順序を保証する。
3.3 保存と復元
バッファはstorage.localへ保存する。

FirefoxやFocodexの再起動後も内容を復元する。

受信バッファと受信済みIDは、同じ`storage.local`レコードとして保存する。保存完了前に送信元へ`accepted`を返さない。
4. 拡張間通信
4.1 通信方式
Firefox標準の拡張間メッセージングを使用する。
- 送信：browser.runtime.sendMessage()
- 受信：browser.runtime.onMessageExternal
既存のNative Hostを経由する必要はない。
4.2 メッセージ形式
{
  "type": "focodex.buffer.receive",
  "version": 1,
  "requestId": "UUID",
  "text": "送信する文章"
}

送信先入力欄を指定するtargetは廃止する。

fox-voice-editorはFocodexの内部構造を認識しない。
4.3 受信側の検証
Focodexは以下を検証する。
1. sender.idが許可された固定IDと一致する。
2. 送信元ページが許可されたeditor.htmlである。
3. メッセージ形式とバージョンが正しい。
4. 本文が文字列である。
5. 本文が空白のみではない。
6. 本文が20,000 UTF-16コード単位以内である。
7. requestIdが有効である。
8. 同一IDの保存済み本文と本文が一致する。
検証失敗時は保存せず拒否する。

送信元IDの検証と頻度制限は、従来案を維持する。
4.4 外部に公開する操作
外部拡張に公開する操作は、受信バッファへの文章追加のみとする。状態照会APIは公開しない。

応答は次の3種類だけとする。

| 応答 | 意味 |
| --- | --- |
| `accepted` | 新規の文章と受信済みIDを保存した。 |
| `duplicate` | 同じID・同じ本文を過去に受理済みであり、追加しなかった。 |
| `rejected` | 認証、形式、本文不一致、頻度制限、保存失敗のいずれかで受理しなかった。 |

以下の操作は公開しない。
- バッファの読み出し・削除
- 入力欄への反映
- Codexの実行・停止
- Git操作
- Native Hostの直接呼び出し
- プロジェクト・権限設定の変更

5.1 受信バッファ
折りたたみ可能なパネルとして設置する。

│                                  │
│ [指示文へ] [削除]                │
│                                  │
├──────────────────────────────────┤
│                                  │
│ ② READMEの説明を更新            │
│                                  │
│ [指示文へ] [削除]                │

空のバッファは表示しない。接続が切れた場合は、パネル内の「受信を再接続」の横に状態を表示する。文章は全文を表示する。
5.2 入力欄への反映
ユーザーがバッファ内の文章と反映先を選択する。

第2段階ではCodex指示文とGitコミットメッセージ欄へ明示反映できる。各欄に独立したUndo・クリアを用意し、反映だけで実行しない。

既存の文章も確認なしで全文置き換えする。反映前の内容は「元に戻す」で1回だけ復元できる。指示文が空でなければ「クリア」を表示し、クリアも同じUndo対象とする。

反映後もバッファの文章は削除しない。

反映操作によってCodexやGitが自動実行されることはない。

Codex、モデル取得、すべてのGit操作の実行中は、バッファ項目の反映・削除を無効化する。
6. Git操作機能の追加
Git操作はCodex CLIから完全に分離する。

FocodexのNative Hostが専用のGit操作を提供する。
6.1 提供する機能
操作	方針
Status	状態確認
Pull	Fast-forwardのみ
Commit	Focodexから明示実行
Push	通常Pushのみ
競合解決	実装しない
Force Push	禁止


6.2 Pull
基本コマンド：
git pull --ff-only

実行条件：
- 登録済みリポジトリである。
- 作業ツリーがクリーンである。
- Git操作が実行中ではない。
- ユーザーが明示的に実行した。
履歴が分岐した場合は停止する。

自動マージ、Rebase、競合解決は行わない。
6.3 Commit
コミットメッセージはFocodexの専用入力欄で保持する。

文章の作成はfox-voice-editorで行い、受信バッファから反映する。

CommitはFocodexのボタンから実行する。

コミット対象はユーザーが明示的に選択する方式を基本とし、無条件のgit add .は使用しない。Hostは、選択されたパスだけをステージし、コミット直前に最終確認したステージ済み差分と実際のインデックスが一致することを検証する。不一致ならコミットせず、状態を再表示する。
6.4 Push
通常のPushのみを許可する。

Force Pushは禁止する。

リモート側の履歴が進んでおり、通常のPushが拒否された場合は停止する。

自動PullやRebaseは行わない。
6.5 権限分離
Codex CLI
  ├─ 登録済みプロジェクトの編集
  ├─ 通常リポジトリとworktreeのGit管理情報は変更不可
  ├─ 外部ネットワーク通信は不可
  └─ Git変更操作のための追加権限は与えない

Focodex Native Host
  ├─ Git Status
  ├─ Git Pull
  ├─ Git Commit
  └─ Git Push

Git操作では、登録済みリポジトリ以外を操作対象にしない。

Git Hostは、固定した引数配列以外を実行しないだけでなく、リポジトリ内・管理ディレクトリ内の設定を信頼しない。フックは無効化し、フィルター、属性から参照されるフィルター、外部diff、fsmonitor、include、SSH・認証ヘルパー・署名・remoteの外部コマンド設定は、操作ごとに許可するものを明示するまで拒否する。`.gitattributes`は作業ファイルなのでCodexが変更できるものとして検査対象に含める。
7. セキュリティ設計の基本方針
今回の変更では、操作を3段階に分離する。
段階	操作主体	許可する操作
① 文章送信	fox-voice-editor	バッファへの文章追加
② 文章反映	Focodexユーザー	反映先の選択と全文置き換え
③ 実行	Focodexユーザー	Codex・Gitの実行


受信した文章を自動的に入力欄へ反映しないことで、外部拡張がFocodexの実行内容を直接変更する経路を排除する。

文章の反映先を選択するのはユーザーの責任とする。

一方、選択した入力欄へ正確に反映すること、反映操作だけで実行されないことはFocodex側で保証する。

なお、許可済み送信元が悪意を持って文章を大量送信した場合、FIFOによって既存の文章が押し出される可能性がある。これは今回のバッファ仕様上の制約として扱い、頻度制限で影響を抑える。
8. 従来案からの変更点
項目	従来案	新方式
受信先	Codex指示文欄	受信バッファ
受信保持件数	1件	3件
受信時の自動反映	条件付きで実施	禁止
送信先指定	targetで指定	不要
入力欄の状態確認	受信時に必要	受信時には不要
未処理受信がある場合	新規受信を拒否	FIFOで最古を削除

反映先	Codex指示文	Codex・Git

9. 実装時の確認事項
実装前に決める必要がある項目は以下のとおり。
1. FIFOで削除された文章を復元できない仕様でよいか。
2. Commit対象ファイルの選択UIをどの程度作り込むか。
3. Gitの追跡ブランチが未設定の場合の扱い。
4. Gitの認証方式と、認証失敗時の扱い。
5. リポジトリ内の`.gitattributes`と管理ディレクトリ内設定を検査する具体的な許可・拒否規則。

排他は初版ではワークスペース全体にかける。Codex実行、Status・差分確認を含むGit操作、Commit、Pull、Pushのいずれかが実行中なら、ほかの操作は待機キューへ入れず拒否する。ロックは実行前の検証から、子プロセス群の終了と実行後状態の確認まで保持する。Codexのキャンセル要求を送った時点では解除しない。

外部ターミナルなどFocodexの外から行われる変更はロックでは防げない。このため、変更するGit操作は直前と直後に状態を再確認する。
10. 段階的な実装

| 段階 | 実装内容 |
| --- | --- |
| 第1段階：受信バッファ | 3件FIFO、受信済みID、`accepted`/`duplicate`/`rejected`、Codex指示文への明示反映、旧自動反映の削除。 |
| 第2段階：Commit | 状態・差分表示、ファイル選択、ステージ内容の最終照合、Commit、Commit欄への明示反映。 |
| 第3段階：Pull・Push | Fast-forward Pullと単一追跡ブランチへの通常Push。認証・リモート・ブランチ・設定の許可規則を確定してから追加。 |

11. まとめ
今回の変更の中心は、次の3点です。

① fox-voice-editorを文章作成専用にする。

Focodex内部の入力欄やGit機能を認識させない。

② Focodexに3件のFIFO受信バッファを設ける。

受信と反映を分離し、反映先はユーザーが明示的に選択する。

③ Git操作をFocodexの独立した権限で実行する。

Codex CLIにはGit操作を許可せず、Pull・Commit・PushはFocodexの専用UIから操作する。

この構成なら、fox-voice-editorとFocodexの独立性を維持しながら、Surfaceのタッチ専用環境で文章作成から開発、コミット、Pushまでを完結できるようになります。

また、将来Focodexに別の文章入力欄が増えても、拡張間通信仕様を変更する必要がありません。

受信バッファを拡張間の境界として固定し、Focodex内部の機能拡張とは切り離す。

これを今回の設計変更の基本方針とします。
